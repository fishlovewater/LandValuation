# 第一子系統逐份輸入與確認設計

## 目標

競賽題目提供的來源資料採逐份處理：一次上傳一份、立即辨識及核對，完成後才進入下一份。每份文件原則上一次確認；只有後端標記為待確認、缺少來源證據或彼此衝突的欄位需要逐筆處理。

## Input 邊界

- F01「買賣實例調查估價表」不是題目提供的 Input，不列入上傳清單，也不得因未上傳而阻擋流程。
- F03「比準地地價估計表」不是題目提供的 Input，不列入上傳清單，也不得因未上傳而阻擋流程。
- 不刪除既有 F01／F03 資料模型、API、計算、migration 或報表輸出；它們仍可作為後續由其他已確認資料產生的系統表單或輸出。
- 實際上傳清單固定為三份題目提供的來源資料，依序為：
  1. 宗地區段地價勘查表。
  2. 比準地價勘查表。
  3. 比較法查估表。
- 每個上傳步驟先顯示該表名稱、用途及可供核對的基本資料，引導使用者選對文件。
- 文件上傳時直接依目前步驟保存明確的文件類型，讓系統知道這份資料屬於哪一表，不只依賴檔名猜測。
- 清單順序固定，並分別顯示待上傳、待核對、已確認或已跳過狀態。

## 操作流程

1. 畫面顯示目前應上傳的來源文件及用途。
2. 使用者一次選擇並上傳一份文件。
3. 畫面並列原文件證據與擷取結果。
4. 正常欄位可隨整份文件一次確認；待確認、缺乏證據或衝突欄位必須逐筆採用、修改或排除。
5. 所有異常欄位處理完後，使用者按「本份文件確認完成」。
6. 系統保存確認值、標記步驟完成並開放下一份文件。
7. 三份文件均已確認或明確跳過後，開放正式資料、計算、檢核與輸出；缺漏資料仍須清楚提示，不自動補值。

## 安全與錯誤處理

- 是否需要逐筆確認沿用後端欄位狀態，不在前端另造信心度算法。
- 上傳、辨識失敗或目前沒有該文件時，使用者可以重試或跳過；跳過不清除前面已確認資料，並保留缺漏提示。
- 已完成文件可返回查看及修正；修改確認值後，相關計算與輸出須重新執行。
- 沒有來源證據的欄位維持空白，不自動臆測。

## 驗收條件

- Input 清單不出現 F01 或 F03，缺少兩者不會阻擋下一步。
- Input 清單依序只顯示宗地區段地價勘查表、比準地價勘查表及比較法查估表。
- 每一步均顯示文件名稱、用途及基本資料，且上傳後保存該步驟指定的文件類型。
- 一次只能處理目前步驟的一份文件。
- 無異常欄位時可按一次完成整份確認。
- 有異常欄位時，未逐筆處理前不能完成該文件。
- 完成或跳過後正確進入下一份；重新載入頁面仍保留進度與跳過狀態。
- 既有 F01／F03 後端及報表能力沒有被刪除或破壞。

## 非目標

- 不支援任意未知格式文件。
- 不重做資料庫 schema、RBAC 或第二至第四子系統。
- 不把 AI／OCR 原始值直接視為正式採用值。
