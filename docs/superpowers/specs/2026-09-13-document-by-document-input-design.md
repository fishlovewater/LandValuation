# 第一子系統逐份輸入與確認設計

## 目標

競賽題目提供的來源資料採逐份處理：一次上傳一份、立即辨識及核對，完成後才進入下一份。每份文件原則上一次確認；只有後端標記為待確認、缺少來源證據或彼此衝突的欄位需要逐筆處理。

## Input 邊界

- F01「買賣實例調查估價表」不是題目提供的 Input，不列入上傳清單，也不得因未上傳而阻擋流程。
- F03「比準地地價估計表」不是題目提供的 Input，不列入上傳清單，也不得因未上傳而阻擋流程。
- 不刪除既有 F01／F03 資料模型、API、計算、migration 或報表輸出；它們仍可作為後續由其他已確認資料產生的系統表單或輸出。
- 實際上傳清單只包含題目確實提供的其他來源資料，清單順序固定並顯示完成狀態。

## 操作流程

1. 畫面顯示目前應上傳的來源文件及用途。
2. 使用者一次選擇並上傳一份文件。
3. 系統只針對該文件適用的欄位執行辨識，不再對每份文件一律分析 F01 至 F04 全部表單。
4. 畫面並列原文件證據與擷取結果。
5. 正常欄位可隨整份文件一次確認；待確認、缺乏證據或衝突欄位必須逐筆採用、修改或排除。
6. 所有異常欄位處理完後，使用者按「本份文件確認完成」。
7. 系統保存確認值、標記步驟完成並開放下一份文件。
8. 所有必要來源完成後才開放正式資料、計算、檢核與輸出。

## 安全與錯誤處理

- 是否需要逐筆確認沿用後端欄位狀態，不在前端另造信心度算法。
- 上傳或辨識失敗時停留在目前文件，允許重試，不跳過也不清除前面已確認資料。
- 已完成文件可返回查看及修正；修改確認值後，相關計算與輸出須重新執行。
- 沒有來源證據的欄位維持空白，不自動臆測。

## 驗收條件

- Input 清單不出現 F01 或 F03，缺少兩者不會阻擋下一步。
- 一次只能處理目前步驟的一份文件。
- 無異常欄位時可按一次完成整份確認。
- 有異常欄位時，未逐筆處理前不能完成該文件。
- 完成後正確進入下一份；重新載入頁面仍保留進度。
- 既有 F01／F03 後端及報表能力沒有被刪除或破壞。

## 非目標

- 不支援任意未知格式文件。
- 不重做資料庫 schema、RBAC 或第二至第四子系統。
- 不把 AI／OCR 原始值直接視為正式採用值。
